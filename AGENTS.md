# Repository workflow

- For each user-requested round of code improvements, finish the changes and relevant checks, then commit and push to the existing upstream unless the user instructs otherwise. This is the project owner’s requested workflow.
- Fetch and compare the remote before uploading. Inspect and resolve any overlapping changes without discarding local or remote work; never force-push.
- Use meaningful commits representing actual work; do not create empty or artificial commits to increase activity.
- Keep databases, credentials, dependencies and temporary test artifacts out of commits. Report checks performed and the verified uploaded commit.
- Organizers manage only events they created. Event times use Australia/Sydney.
