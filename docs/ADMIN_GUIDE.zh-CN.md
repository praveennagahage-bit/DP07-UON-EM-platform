# 管理员与本轮 Demo 指南

## 配置管理员
先在网站正常注册一个专门用于管理的账号，再在项目根目录运行：

```sh
npm run admin:grant -- 你的已注册邮箱 --confirm
```

命令使用与后端相同的 DB_PATH（未设置时为项目 users.db）。请确认终端指向正确数据库。该账号会从原角色改为 Admin，已有登录会话失效，需要重新登录。网站注册页和 Profile 都不能提升权限。没有预设管理员密码；本轮开发没有更改真实账号角色。

重启后端会自动添加 users 的 bio、status、banReason 字段及 admin_audit 表，保留已有用户、事件和报名。无需给每个人另建数据库。

## 权限与处理规则
- Attendee：管理自己的报名和资料。
- Organizer：创建活动，只管理自己创建的活动及参加者。
- Admin：Administration 查看全站账号与活动，封禁/解封普通账号，跨 Organizer 编辑、取消或删除活动。
- Admin 不通过页面封禁自己或其他 Admin。封禁立即撤销全部会话，阻止登录和新增报名；解封后需要重新登录。已有活动和报名保留，管理员按需要单独处理。
- 有报名的活动只能取消并通知当前参加者；零报名活动才可永久删除。取消后不允许编辑或重新开放。
- 管理操作必须填写原因，记录操作者、时间、目标和变更。记录写入失败时，操作一起回滚。
- Activity Log 每次读取最多 50 条，可继续加载。账号与活动列表可搜索筛选。

## 本轮演示（约 5–7 分钟）
1. Organizer 打开 Create Event：输入超过 30 字符的标题、超过 500 字符的描述、地点 123 或小数容量，展示阻止提交及字段提示。改成 JS Workshop、Room 201、20 和未来时间，上传 photos 中的图片后创建。
2. 展示合法的 JavaScript 课程名称仍能保存。HTML 标签、脚本 URL 和控制字符会被拒绝；内容始终作为普通文本显示。字符数按去除首尾空白后的 Unicode 字符计数，包含中间空格和标点，不按英文单词数。
3. Update Profile 修改姓名和简介，保存后导航更新，刷新仍保留。邮箱、角色只读。
4. 展示首页和 Events 中不同长度内容的卡片：标题/地点/描述过长省略，View Details 底部对齐，详情仍保留全文。
5. Admin 登录 → Administration → Users，封禁演示用 Attendee；该用户不能继续登录。解封后可以重新登录。不要使用真实组员账号演示封禁。
6. All Events 进入另一位 Organizer 的活动，填写原因并编辑；其创建者不变。让 Attendee 报名后，Admin 取消活动，Attendee 在铃铛和 My Bookings 查看原因。Activity Log 查看上述记录。
7. 浏览器切换 360、390、430 像素宽度，展示侧栏堆叠、表单和卡片。开发检查使用浏览器视口模拟，真实手机的软键盘和触摸体验仍建议现场补测。

## 输入规则与旧数据
标题最多 30 字符、描述 500、地点 120；地点必须包含文字（Room 201 / Online 均可）。容量为 1–10000 的整数，不能低于现有报名人数。姓名每项最多 50 字符，简介 300。

旧活动不会自动截断或删除；若内容超过新限制，编辑保存前必须缩短。日期仍按 Australia/Sydney 校验。

## 验证记录
本轮 30 项自动测试通过，覆盖输入边界、资料隔离、管理员配置/权限、封禁会话撤销、全站活动管理、通知、失败回滚和并发操作；前端 ESLint 与生产构建通过。浏览器使用隔离内存数据库，验证资料保存、图片上传创建、时间选择、管理员编辑/封禁/解封/取消、管理记录和取消通知。现有 users.db 未用于这些测试。

## 管理操作通知更新
标题上限现为 30 字符。管理员每次编辑活动均通知创建者，展示理由与字段修改前后内容；取消活动通知创建者及当前报名者；永久删除零报名活动也通知创建者，保留活动名和理由。无关 Organizer 不接收通知。通知、操作与审计记录同一事务提交，失败时全部回滚。旧操作不会补发通知。当前没有独立“下架”状态，继续使用取消或零报名删除流程。
