# 管理员与本轮 Demo 指南

## 配置管理员
先在网站正常注册一个专门用于管理的账号，再在项目根目录运行：

```sh
npm run admin:grant -- 你的已注册邮箱 --confirm
```

命令使用与后端相同的 DB_PATH（未设置时为项目 users.db）。请确认终端指向正确数据库。该账号会从原角色改为 Admin，已有登录会话失效，需要重新登录。网站注册页和 Profile 都不能提升权限。没有预设管理员密码；本轮开发没有更改真实账号角色。

重启后端会自动添加 users 的 bio、status、banReason 字段及 admin_audit 表，保留已有用户、事件和报名。无需给每个人另建数据库。

## 权限与处理规则
- Attendee：管理自己的报名和资料。
- Organizer：创建活动，只管理自己创建的活动及参加者。
- Admin：Administration 查看全站账号与活动，封禁/解封普通账号，跨 Organizer 编辑、取消或删除活动。
- Admin 不通过页面封禁自己或其他 Admin。封禁立即撤销全部会话，阻止登录和新增报名；解封后需要重新登录。已有活动和报名保留，管理员按需要单独处理。
- 有报名的活动只能取消并通知当前参加者；零报名活动才可永久删除。取消后不能编辑；管理员可填写理由恢复尚未开始的活动。
- 管理操作必须填写原因，记录操作者、时间、目标和变更。记录写入失败时，操作一起回滚。
- Activity Log 每次读取最多 50 条，可继续加载。账号与活动列表可搜索筛选。

## 本轮演示（约 5–7 分钟）
1. Organizer 打开 Create Event：输入超过 30 字符的标题、超过 500 字符的描述、地点 123 或小数容量，展示阻止提交及字段提示。改成 JS Workshop、Room 201、20 和未来时间，上传 photos 中的图片后创建。
2. 展示合法的 JavaScript 课程名称仍能保存。HTML 标签、脚本 URL 和控制字符会被拒绝；内容始终作为普通文本显示。字符数按去除首尾空白后的 Unicode 字符计数，包含中间空格和标点，不按英文单词数。
3. Update Profile 修改姓名和简介，保存后导航更新，刷新仍保留。邮箱、角色只读。
4. 展示首页和 Events 中不同长度内容的卡片：标题/地点/描述过长省略，View Details 底部对齐，详情仍保留全文。
5. Admin 登录 → Administration → Users，封禁演示用 Attendee；该用户不能继续登录。解封后可以重新登录。不要使用真实组员账号演示封禁。
6. All Events 进入另一位 Organizer 的活动，填写原因并编辑；其创建者不变。让 Attendee 报名后，Admin 取消活动，Attendee 在铃铛和 My Bookings 查看原因。Activity Log 查看上述记录。
7. 浏览器切换 360、390、430 像素宽度，展示侧栏堆叠、表单和卡片。开发检查使用浏览器视口模拟，真实手机的软键盘和触摸体验仍建议现场补测。

## 输入规则与旧数据
标题最多 30 字符、描述 500、地点 120；地点必须包含文字（Room 201 / Online 均可）。容量为 1–10000 的整数，不能低于现有报名人数。姓名每项最多 50 字符，简介 300。

旧活动不会自动截断或删除；若内容超过新限制，编辑保存前必须缩短。日期仍按 Australia/Sydney 校验。

## 管理操作通知更新
标题上限现为 30 字符。管理员每次编辑活动均通知创建者，展示理由与字段修改前后内容；取消活动通知创建者及当前报名者；永久删除零报名活动也通知创建者，保留活动名和理由。无关 Organizer 不接收通知。通知、操作与审计记录同一事务提交，失败时全部回滚。旧操作不会补发通知。当前没有独立“下架”状态，继续使用取消或零报名删除流程。

## 恢复活动
Admin 打开已取消活动详情，填写 Management reason，点击 Restore Event。仅允许恢复尚未开始的活动，保留原报名，清除当前取消原因并重新开放报名。原取消原因保留在通知及审计记录中。恢复通知发送给创建者和当前报名者；重复恢复被拒绝，再次取消会生成新通知。Organizer 无恢复权限。

## 管理员分配与通知规则（2026-10-15）

初始 Admin：首次部署先注册负责人账号，再执行一次 `npm run admin:grant -- 邮箱 --confirm`。数据库已有 Admin 时，命令不能再提升其他账号；现有 Admin 保留，不自动创建通用密码账号。

后续分配：Admin 登录 → Administration → Users → Grant admin access，填写理由并确认。撤销时选 Revoke admin access，选择恢复为 Attendee 或 Organizer，填写理由。已有活动和报名不会被删除或转移。至少保留一位有效 Admin；暂停账号须先恢复才能变更角色。每次角色调整记录操作人、时间、对象、前后角色和原因，并通知该用户、撤销其所有登录会话，要求重新登录。

| 操作 | 通知对象 |
| --- | --- |
| Admin 编辑活动 | 创建者；文字信息发生变化时也通知当前报名者 |
| Organizer 编辑活动文字信息 | 当前报名者 |
| Admin 取消、恢复活动 | 创建者和当前报名者 |
| Organizer 取消活动 | 当前报名者 |
| Organizer 代报名、移除参加者 | 被操作的用户 |
| Admin 永久删除零报名活动 | 创建者 |
| Admin 授予、撤销管理员角色 | 被调整账号 |

文字信息包括标题、描述、日期、时间、地点、类别、容量。通知保留理由及实际修改前后内容。Organizer 编辑/代报名/移除可以填写说明，未填写时使用明确的系统操作说明。单纯换图或没有实际文字变化时，不通知报名者；Admin 编辑仍通知创建者。无关 Organizer、已自行退订的用户不接收后续活动变更通知。

通知与对应操作在同一数据库事务内完成，失败时一起回滚。旧操作不补发。通知中心支持所有通知类型，账户通知不显示活动链接。

验证：35 项自动测试、ESLint 和生产构建通过。测试使用独立数据库，没有修改真实账号权限或报名数据。

## 关键词拦截与用户举报（2026-10-16）

### 关键词名单
Admin → Administration → Keywords。填写 Phrase（2–100字符）及管理理由，Confirm 后立即启用。每条规则可 Disable rule / Enable rule，需填写理由并记录审计。初始名单为空，由管理员制定具体规则，不预置宽泛的政治、宗教等词汇名单。

所有角色的活动创建/编辑均由后端检查标题、描述、地点。启用短语以普通文本子串匹配，忽略大小写、全角形式、重复空白和零宽字符。命中会拒绝保存并指出字段；原活动保持原样。不是正则规则，也不具备语义理解或图片审核能力，可能误判。新增规则不追溯删除已有活动。

### 举报与处理
登录用户打开活动详情 → Report Event → 填写 Report reason → Submit Report。
同一账号对同一活动只能有一条待处理举报，每小时最多5条。举报不会自动取消、封禁或删除活动。

Admin → Administration → Reports → Review Event 查看活动。需要取消时使用现有活动管理操作；随后 Review Report，选择 Resolved（已处理）或 Dismissed（无需处理），填写 Response to reporter 后确认。该回复发送给举报人，处理结果进入 Activity Log。举报人身份不向 Organizer 展示。活动删除后举报及通知快照仍保留。

### Demo
1. 添加“演示拦截词”，Organizer 在描述中输入它后提交，展示拒绝保存；编辑已有活动也会拦截。
2. Admin 停用该规则，展示相同内容可以保存。
3. Attendee 举报活动；重复提交会提示已有待处理举报。
4. Admin 在 Reports 审查并回复，切回举报用户，在 Notifications 查看结果。
5. 如需处理活动，Admin 另行取消，创建者和当前报名者收到原有取消通知。
