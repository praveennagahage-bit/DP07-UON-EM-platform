# 2026-10-29 功能与演示指南

## AI 审核配置

重启后端 npm start，前端在 client 目录运行 npm run dev。数据库启动时自动增加发送记录表，保留原有数据。

将根目录 .env.example 复制为 .env，在本机填写 OPENAI_API_KEY，保持 AI_MODERATION_MODE=required 后重启后端。不要将密钥发到 Discord、前端代码或 Git。npm start 自动读取根目录 .env；直接执行 node server.js 时需预先设置环境变量。

- 接口：OpenAI POST /v1/moderations，模型 omni-moderation-latest。
- 没有 key 且未指定模式时使用 keywords 模式；面板和活动编辑页明确显示 AI 未启用。
- required 模式缺少 key、超时、接口失败或结果无效时拒绝保存，不静默跳过。
- keywords 模式仅使用本地关键词，不向外部服务发送内容。
- 创建及编辑（包括 Admin 编辑）均审核标题、描述、地点。图片及历史活动不在本轮 AI 审核范围。
- 字段验证及关键词检查先执行；每账号每分钟最多 10 次 AI 审核尝试，超时 8 秒。
- 使用服务返回的 flagged 判定，不自行设置未经校准的分数阈值。误判时提示修改或联系管理员复核。
- 只发送活动文本，不发送账号、密码和报名者信息。用户举报与人工管理继续保留。
- 当前环境没有 API key；本轮通过模拟响应验证放行、拦截、异常及超时，真实服务调用仍需配置后验收。

官方说明：https://developers.openai.com/api/docs/guides/moderation

## 统计面板

Admin 登录后进入 Administration → Overview，查看用户总数、角色分布、有效/封禁人数、活动数量、未来/已开始/取消活动、报名次数、独立报名人数、有效活动报名数、待处理举报数。

Refresh statistics 更新数据。角色人数包含封禁账号；取消活动单独分类；总报名包含取消后保留的报名；报名次数不等于独立人数。活动时间及快照按 Australia/Sydney。其他角色不能访问全站统计。

## 主动通知

- Admin：Administration → Messages，搜索勾选有效账号（含 Organizer），填写标题和正文并发送。最多选择 100 个直接收件人。
- Admin 或活动所属 Organizer：活动详情 → Message registered attendees，发送给该活动当前有效账号的报名者。
- Organizer 不能给其他人的活动发消息或指定全站用户。首版不开放 Organizer 间的直接消息和全站广播。
- 已取消活动仍可通知原报名者；无有效收件人时拒绝发送。
- 标题 100 字符、正文 1000 字符，纯文本；每发送者每分钟最多 5 次。
- 通知显示发送时姓名、角色、正文及时间；活动消息带活动链接。直接消息不会误显示活动已删除。
- 复用铃铛和未读/已读机制。发送区可查看本人最新 50 次发送记录；活动页只显示其中对应活动的记录。
- 收件人去重；发送记录和通知写入同一事务，失败不会部分送达。
- 不包含邮件、回复或即时聊天。

Demo：Organizer 给自己活动报名者发“Please bring water”，切换报名者打开 Notifications，查看并标记已读；Admin 再直接给 Organizer 发消息并查看。

## 按钮布局

Administration → Users 的授权和封禁/恢复按钮统一宽度，间隔 12px、最小高度 44px；文字可换行。Admin 单按钮卡片保留保护说明。检查桌面与窄屏布局。
